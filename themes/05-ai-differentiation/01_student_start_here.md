# 01. Регламент запуска

---

## Назначение работы
Тема строится как учебный цикл с четкой логикой переходов: от диагностики стартового уровня к проектированию содержания и затем к автоматической маршрутизации.  
Такой порядок обеспечивает не только полноту выполнения задания, но и педагогическую прозрачность результата.

Итог оформляется тремя артефактами:
1. `A1` — входные параметры и предтест;
2. `A2` — три версии содержания по уровням;
3. `A3` — подтвержденный маршрут выдачи уровня.

---

## Ключевые понятия
- `A1`: структурированный паспорт модуля и предтест.  
  Почему это важно: без формальной диагностики невозможно обоснованно выбрать уровень сложности.
- `A2`: дифференцированный комплект `basic/standard/advanced`.  
  Почему это важно: единая тема должна сохраняться, а уровень учебного действия — изменяться.
- `A3`: протокол `Yandex Forms -> Albato -> Google Sheets`.  
  Почему это важно: назначение уровня должно подтверждаться журналом, а не субъективной интерпретацией.

---

## Сквозной демонстрационный образец
Для пояснения логики в документации используется нейтральный пример:
- `discipline`: информатика;
- `topic`: ветвление в алгоритмах (`if/else`);
- `audience`: 1 курс СПО;
- `learning_goal`: выбор ветви алгоритма по условию и объяснение причин выбора.

Образец служит только методической опорой и не подменяет индивидуальную тему итогового результата.

---

## Последовательность выполнения
Переход к следующему шагу выполняется после фиксации результата предыдущего шага.

1. Сборка `A1` по файлу `02`.
2. Сборка `A2` по файлу `03`.
3. Сборка `A3` по файлу `04`.
4. Выполнение практики A-core по файлу `05`.
5. Выполнение одного варианта части B по файлу `06`.
6. Итоговая проверка по рубрике из файла `07`.

---

## Пояснение к последовательности
### Переход
Последовательность начинается с `A1`, поскольку именно этот артефакт задает входные условия и уровень.

### Почему это важно
Если начать с проектирования `A2` без `A1`, дифференциация уровней теряет диагностическое основание.

### Короткий пример
При значении `score = 2` формируется старт `basic`; это влияет на глубину заданий, которые закладываются в `A2`.

---

## Операционный контур выполнения

| Этап | Действие | Ожидаемый результат | Фиксация результата |
|---|---|---|---|
| `A1` | формализация исходных параметров и диагностики | назначение уровня по шкале | файл `A1` |
| `A2` | проектирование трех уровней содержания | различимые уровни с checkpoint | файл `A2` |
| `A3` | настройка и проверка маршрута | автоматическая регистрация уровня | файл `A3` |
| `B` | ограниченная доработка | подтвержденный прирост качества | отдельный результат B |

---

## Нормативные требования
1. Предтест содержит `6` вопросов.
2. Уровень определяется только по шкале:
   - `0-2` -> `basic`,
   - `3-4` -> `standard`,
   - `5-6` -> `advanced`.
3. Для каждого уровня в `A2` фиксируются `checkpoint_test` и `checkpoint_key`.
4. В `A3` подтверждаются сценарные прогоны `2/6`, `4/6`, `6/6`.

---

## Входной самоконтроль
1. Зафиксированы `discipline` и узкий `topic`.
2. Подготовлен формат трех отдельных файлов (`A1`, `A2`, `A3`).
3. Понятна роль каждого артефакта в общей логике выполнения.

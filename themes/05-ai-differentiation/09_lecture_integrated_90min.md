# 09. Интегрированный сценарий на 90 минут

---

## Логика сценария
Интегрированный сценарий объединяет весь цикл темы в одном занятии.  
Последовательность построена так, чтобы каждый следующий шаг опирался на артефакт предыдущего шага.

Итогом сценария являются:
1. `A1` — заполненный диагностический контур;
2. `A2` — три дифференцированные версии содержания;
3. `A3` — подтвержденный маршрут автоматического назначения уровня.

---

## Сквозной демонстрационный образец
Для методической связности используется демонстрационный образец:
- `discipline`: информатика;
- `topic`: ветвление в алгоритмах (`if/else`);
- `audience`: 1 курс СПО;
- `learning_goal`: корректный выбор ветви алгоритма по условию.

Этот образец используется только для иллюстрации переходов между шагами.

---

## Ключевые понятия
- `адаптивный модуль`: набор материалов с вариативностью по уровню сложности.  
  Почему это важно: позволяет соотнести глубину задания с реальной подготовкой.
- `маршрутизация`: автоматическое сопоставление `score` и `assigned_level`.  
  Почему это важно: исключает произвольное распределение по уровням.
- `артефакт`: документированный результат этапа.  
  Почему это важно: обеспечивает проверяемость без устной расшифровки.

---

## Тайминг занятия

| Интервал | Блок | Целевое действие | Выходной артефакт |
|---|---|---|---|
| 0-10 | запуск | фиксация регламента и кейса | зафиксирован план выполнения |
| 10-35 | `A1` | сборка паспорта и предтеста | черновик `A1` |
| 35-60 | `A2` | проектирование трех уровней | черновик `A2` |
| 60-75 | `A3` | настройка линейного потока | черновик `A3` |
| 75-85 | контроль | прогоны `2/6`, `4/6`, `6/6` | `run_evidence`, `result_log` |
| 85-90 | итог | сверка полноты результата | финальные `A1/A2/A3` |

---

## Блок 1. Сборка A1
### Переход
После фиксации регламента необходимо сформировать диагностическую основу маршрута.

### Почему шаг необходим
Без `A1` невозможно обоснованно определить, какой уровень должен быть выдан в `A3`.

### Действие
Заполняются поля `A1`, формируется `pretest_6q`, подсчитывается `score`, фиксируется `assigned_level`.

### Ожидаемый результат
Уровень назначен по формальной шкале без дополнительных интерпретаций.

### Фиксация результата
Заполненный артефакт `A1`.

### Короткий пример
В демонстрационном кейсе значение `score = 3` фиксирует `assigned_level = standard`.

---

## Блок 2. Сборка A2
### Переход
После назначения стартового уровня требуется развернуть тему в три версии сложности.

### Почему шаг необходим
Маршрутизация без подготовленных уровней не дает практического эффекта.

### Действие
Для каждого уровня заполняются `theory`, `practice_block`, `checkpoint_test`, `checkpoint_key`, `criteria`, `teacher_notes`.

### Ожидаемый результат
Три уровня отличаются типом учебного действия, а не только объемом текста.

### Фиксация результата
Заполненный артефакт `A2`.

### Короткий пример
`advanced` включает задачу на анализ ошибочного условия в коде `if/else`.

---

## Блок 3. Сборка A3
### Переход
После подготовки содержания необходимо связать предтест и выдачу уровня в едином потоке.

### Почему шаг необходим
Именно `A3` подтверждает, что адаптивность работает в фактическом режиме, а не только в описании.

### Действие
Фиксируется и настраивается маршрут `Yandex Forms -> Albato -> Google Sheets`, заполняются `flow_steps`, `field_mapping`, `routing_rules(2/4/6)`.

### Ожидаемый результат
Маршрут записывает корректный уровень и ссылку на материал в журнал.

### Фиксация результата
Черновой артефакт `A3`.

### Короткий пример
Поле `assigned_level` в журнале автоматически принимает значение `basic` при `score = 2`.

---

## Блок 4. Контрольные прогоны
### Переход
После конфигурации маршрута требуется подтвердить его поведение на тестовых входах.

### Почему шаг необходим
Без прогона не подтверждается, что правила маршрутизации корректны в реальном выполнении.

### Действие
Выполняются сценарии:
1. `2/6` -> `basic`,
2. `4/6` -> `standard`,
3. `6/6` -> `advanced`.

### Ожидаемый результат
Все сценарии отражены в `result_log` без расхождения со шкалой.

### Фиксация результата
Разделы `run_evidence` и `result_log` в `A3`.

### Короткий пример
Три последовательные записи в журнале демонстрируют корректный переход уровней по мере роста `score`.

---

## Выходной контроль занятия
1. Сформированы три отдельных файла `A1`, `A2`, `A3`.
2. Поля артефактов соответствуют контракту.
3. Шкала уровня применена единообразно.
4. Подтверждены три сценарных прогона.
